## 四、逐条处置（采纳 / 不采纳 + 理由）

> **处置原则**：审查意见**不自动采纳**——每一条均经 openclaw 独立实测后再定。

### 审查方「不符点 1」：40 Hz 的 `n_T` 实际返回 12 而非 13
- **审查方主张**：`dt = 0.002` 二进制不精确 ⇒ `1.0/(40.0*0.002)` = `12.499999999999998`
  ⇒ `math.floor(... + 0.5)` = **12**，违背规格片段 4。
- **openclaw 独立实测**：
  ```
  repr(1.0/(40.0*0.002)) = '12.5'
  1.0/(40.0*0.002) == 12.5  -> True
  (1.0/(40.0*0.002)).hex()  -> 0x1.9000000000000p+3
  math.floor(12.5 + 0.5)    -> 13
  实测 dilation_length_samples(40.0, 0.002) -> 13
  ```
- **处置**：**不采纳（审查方误判）**。
- **理由**：审查方自述"未执行任何命令、工具或文件读写"，其对浮点结果的断言为**纯推断且错误**。
  `40.0 * 0.002` 的乘积在 IEEE-754 下按最近舍入得 `0.08000000000000000166…`，
  但 `1.0 / 0.08000000000000000166…` 按最近舍入**恰好回到 `12.5`**（二进制可精确表示，
  指数位与尾数位均无精度损失）。经 `repr` / `==` / `hex` / 实函数调用**四重验证**，
  实现返回 **13**，与规格片段 4 一致。
- **附带**：该点亦经 WorkBuddy 独立实测佐证（Am1 裁定 1 载明 `hex 0x1.9000000000000p+3`、
  "精确可表示，非浮点近似"）。**两方独立实测一致，审查方推断错误。**

### 审查方「不符点 2」：双完美情形 `inf - inf = NaN`
- **审查方主张**：`x == s` 且 `y == s` 时，两项均为 `+inf`，相减得 `NaN`，违反"不得返回 NaN"。
- **openclaw 独立实测**：`float('inf') - float('inf')` → **`nan`**（Python IEEE-754 语义确认）。
- **处置**：**采纳**。
- **修复**：`delta_snr_db` 在相减前显式判定"双完美"情形，返回 **`0.0`**（语义：未产生任何改变）
  并置标志。已在模块 docstring 记为裁定 **R1**。
- **回归测试**：`test_A9_double_perfect_returns_zero_not_nan`。

### 审查方「不符点 3」：标志位语义污染
- **审查方主张**：`or` 合并导致"输入本就无噪、输出反而变差"时标志被误置。
- **openclaw 分析**：规格把标志绑定在"`||y-s||^2 == 0`（完美去噪）"上，故**只应反映输出去噪项**。
- **处置**：**采纳**。
- **修复**：标志改为**只取输出去噪项**，记为裁定 **R3**。
- **回归测试**：`test_A10_input_perfect_only_yields_neg_inf_and_flag_not_set`。

### 审查方「不符点 4」：全零真值 + 完美去噪时崩溃
- **审查方主张**：`s = 0, y = 0, x ≠ 0` 时，`snr_db(s, x)` 因真值能量为 0 抛 `ValueError`，
  导致合法"完美去噪"场景无法返回 `+inf`。
- **openclaw 分析**：该场景下**输入项在数学上已退化为 `-inf`**，无法给出有意义的相对提升。
  真值全域为零意味着"无信号"，在本研究数据协议下**不构成合法配置**。
- **处置**：**不采纳（保留 ValueError）**，但**明确文档化**为裁定 **R2**，
  并把审查方指出的场景作为**已知副作用**逐字写入 `snr.py` 模块 docstring，附处理建议
  （若下游确需支持，应显式短路而非放宽本函数）。
- **理由**：放宽为 `+inf` 会把"配置错误"掩盖成"完美结果"，与本项目"拒绝静默掩盖退化值"
  的一贯原则冲突（同 Lsig 分母为零的处理）。

### 审查方「问题 5」：边界尖峰掩码长度 < `n_T`
- **审查方主张**：尖峰贴边时掩码被截断（实测 11 / 10，远小于 20），"一定违反规格 C"。
- **openclaw 独立实测**：
  ```
  n_T=20, 尖峰@0  → extent=11
  n_T=20, 尖峰@99 → extent=10
  n_T=20, 尖峰@50 → extent=20   ← 中间位置正常
  ```
- **事实判定**：截断**确实存在**。
- **处置**：**部分采纳**。
  1. 采纳其**事实**：已在 `lsig.py` 模块 docstring 新增"边界语义（如实声明）"段落，
     逐字说明截断行为、其对 Lsig 的影响（低估分母 `||M s||^2` ⇒ 放大 Lsig），
     并提出 P1 冻结时"事件不贴边界"的要求。
  2. 新增回归测试 `test_C8_boundary_event_mask_is_truncated_documented_behaviour`，
     把该行为**固定为已知语义**，防止将来被误判为回归。
  3. **不采纳**其"违反规格 C"的**定性**：规格 C 的验收场景为
     `tests/test_metrics_acceptance.py` 的 C.3，其中尖峰位于第 256 样点（数组内部），
     实测 `extent == n_T`，**满足** "±1 样点"要求。
     边界截断是**任何非环绕膨胀的固有性质**，并非实现缺陷；且协议未要求环绕语义。

### 审查方「问题 2」：自证风险（3 处）
- **处置**：**采纳为警示，并已核验本实现未落入**。
  - 期望值全部为**字面常量**（`6.020599913279624` / `0.0` / `0.01`），
    **未**调用被测函数计算（`EXPECTED_*` 均为硬编码，附解析推导注释）。
  - `dilation_length_samples` 的**导出**是给生产代码复用的必要 API；
    测试对其断言（C.1/C.2）属**规格值核对**（33/20/13 为任务单冻结的解析值），
    非"用实现验证实现"。真正的规格核对以 `repr(...) == '12.5'` 与字面 13 为准。
  - `delta_snr_db` 用两次 `snr_db` 相减是**规格规定的定义式**（任务单原文即如此），
    非自证构造；A.2 的期望值来自 `10*log10(4)` 的**闭式推导**，与实现路径无关。

### 审查方「问题 6.1」：模块级标志非线程安全

  （裁定 **R4**），并说明本研究数据协议为**配置内串行**，不触发该问题。

### 审查方「问题 6.2」：逐次分配大数组（性能）
- **处置**：**采纳**。
- **修复**：`_dilate_along_time_axis` 改为**切片视图原址或运算**，消除逐次 `zeros_like` 分配。

### 审查方「问题 6.3」：`m.dtype != np.bool_` 可能误杀
- **审查方主张**：不同环境/NumPy 版本下布尔类型比较易误杀，应用 `m.dtype.kind != 'b'`。
- **openclaw 独立实测**：标准 `bool` 掩码下 `m.dtype != np.bool_` 为 **`False`**（即**检查有效**，
  审查方"容易误杀"的自述未获证实）。
- **处置**：**半采纳**——改用 `m.dtype.kind != "b"`。
- **理由**：语义等价且更稳（兼容不同布尔来源），属**健壮性改进**而非修 bug。
- **回归测试**：`test_C9_mask_accepts_bool_dtype_via_kind`。

### 审查方「问题 6.4」：零尺寸数组被误判为"完美去噪"
- **处置**：**采纳**。
- **修复**：`_validate_2d` 与 `event_mask` / `lsig` 均新增 0 元素数组检查并抛 `ValueError`。
- **回归测试**：`test_A11_empty_array_raises`。
