A. 裁定 1 —— n_T 取整规则（冻结参数，立即生效）
════════════════════════════════════════════

WorkBuddy 独立实测（venv Python 3.12.10）：
  f=15 Hz: 1/(f·dt) = repr 33.333333333333336 → round()=33, floor(x+0.5)=33
  f=25 Hz: 1/(f·dt) = repr 20.0              → round()=20, floor(x+0.5)=20
  f=40 Hz: 1/(f·dt) = repr 12.5（hex 0x1.9000000000000p+3，**精确可表示，非浮点近似**）
                                             → round()=12, floor(x+0.5)=**13**
  佐证：40*0.002 = 0.08（repr 精确），1/(40*0.002) = 12.5。

**裁定：采用真·四舍五入（half-up），实现为**

    n_T = math.floor(1.0 / (f_main * dt) + 0.5)

  15 / 25 / 40 Hz 对应 n_T = **33 / 20 / 13**（与原单 L53 一致）。

**理由（四条，缺一不可）**
1. 原单（哈希已冻结）明写"应得 33 / 20 / 13"。若改判 12，等于让一份刚冻结的规范文本当天失效，
   不可变性原则即刻崩塌——冻结件的期望值必须成立。
2. **可复现性**：banker's rounding 是 Python 实现细节。用 MATLAB / Fortran / Julia 复现者
   会得到 13，与 12 冲突 → 复现失败。本项目核心主张就是可复现。
3. banker's rounding 的用途是大量数值求和时的统计无偏，与本场景无关；此处无任何技术收益。
4. 你自己承认 R4 原表述"四舍五入取整，Python 内建 round 行为"自相矛盾 → 说明当初并非有意选择，
   而是默认值。

**禁止**：`round()`、`np.round()`、`np.rint()`（三者均为 ties-to-even）；`floor` / `ceil` / 截断。
**要求**：
- 代码中对该 tie case 显式注释（注明 12.5 精确、内建 round 会给 12、本项目取 13）；
- 测试须含专设用例：断言 `repr(1.0/(40.0*0.002)) == '12.5'` 且 `n_T == 13`；
- execution-log 记录三频 `x` 的**完整精度 repr** 与所得 n_T，形成实测证据。
- R4 原注记的措辞错误，以**追加 amendment 条目**更正（不得改动历史条目）。

**P1 冻结表述（照此写入 configs/frozen.yaml）**：
  `n_T_expr = "1/(f_main*dt)"`、`n_T_rule = "half_up: math.floor(x + 0.5)"`、`n_T_int` 逐配置
  （15→33 / 25→20 / 40→13），并同记录该配置的 f_main 与 dt。
