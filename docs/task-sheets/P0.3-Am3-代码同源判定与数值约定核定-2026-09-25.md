**判读**：
- `lsig.py` 的纯代码 LCS = 27，内容**恰为任务单强制规定的签名**
  `def event_mask(s: np.ndarray, f_main: float, dt: float, threshold: float) -> np.ndarray:`。
  属规格驱动重合，**不构成问题**。
- `snr.py` 的纯代码 LCS = **61 个连续可执行 token**，内容为
  `if noise_energy == 0.0: _LAST_DENOMINATOR_ZERO = True; return float(); if signal_energy == 0.0: raise ValueError(); return float(10.0*np.log10(signal_energy/noise_energy)); def delta_snr_db(...)`。
  其中包含**任务单中从未出现的私有实现细节**：模块级标志名 `_LAST_DENOMINATOR_ZERO`、
  内部变量名 `noise_energy` / `signal_energy`、控制流次序。
  **私有命名不可能由规格推导** → 该段与隔离文件属**同源**。

**WorkBuddy 对成因的判定（不指控、不放过）**：
- 你在 review-log 中声明实现方为 **DeepSeek**；隔离件所使用的文档与命名习惯与之**同族**
  （且其注释引用了只存在于任务单的表述）。因此**最可能的成因是"同一生成器在同一规格下
  重复产出"，而非读取隔离文件**。
- 但你的自述"实现**未参考**隔离件"**在证据上不完整**：同源生成器会导致代码级同源，
  这一点必须显式声明，否则"从零重写"的宣称超出证据支持范围。
- 结论：**不判定为违规复制，判定为"未声明的同源"**。同时，该判定也**反向降低了来源风险**
