一、收集守卫规则细化（修正 Am1 裁定 3 的过粗表述）
════════════════════════════════════════════

**你的指认成立**：Am1 裁定 3 写的"断言 `tests/` 下每个 `.py` 以 `test_` 开头"过粗——
它会误伤合法的辅助模块（如 `conftest.py`、被测辅助模块 `ref_forward.py`），
这是**签发方的规则缺陷**，不是你的执行问题。裁定如下（替代原表述）：

**新规则（三条，全部机械可判）**

1. **真绿守卫（核心，直击"假绿"成因）**：
   `tests/` 下任何**定义了顶层 `def test_*` 或 `class Test*`** 的 `.py` 文件，
   **必须**命名为 `test_*.py`；否则 fail。
   依据：假绿的根因是"定义了测试却不被收集"，此条直接针对该根因，与文件命名无关。
2. **清单守卫（防静默堆积）**：`tests/` 下**不定义测试**的 `.py` 文件，
   必须或为 `conftest.py`，或在**显式清单** `tests/_auxiliary.tsv` 中登记，
   每行格式：`文件名<TAB>用途<TAB>被谁导入`。
   清单变更（增删行）时须在 execution-log 记一行；WorkBuddy 审计时会核对清单与实际文件一致。
3. **收集计数守卫**：`tests/test_naming_convention.py` 之外，
   `run_tests.ps1` 输出的 collected 数须与本批 execution-log 记录一致（沿用 Am1 裁定 3 第 3 条）。

**`ref_forward.py` 处置**：登记入 `tests/_auxiliary.tsv`，用途写"独立参考实现（被测辅助模块）"，
被谁导入写 `test_data_acceptance.py`。**不使用代码内豁免名单**——
豁免若写成 `if name in [...]: skip`，守卫会随时间被"顺手加名字"掏空；
清单文件是显式、可审计、可 diff 的载体。

二、指标 API 兼容约束（R9 的边界，必须遵守）
════════════════════════════════════════════

你对 R9 的机制设计（哨兵取代模块级全局标志）**已获批准**，但**不得改变既有公开签名**：

| 函数 | 冻结签名（不得变） | 说明 |
| :--- | :--- | :--- |
| `snr_db(s, x)` | `-> float` | 完美输出时返回 `math.inf` |
| `delta_snr_db(s, x, y)` | `-> float` | `x==s 且 y==s` 时返回 `0.0` |
| `event_mask(s, f_main, dt, threshold)` | `-> np.ndarray` | 不变 |
| `lsig(s, y, mask)` | `-> float` | 不变 |
| `dilation_length_samples(f_main, dt)` | `-> int` | 不变 |

**理由**：① P0.3 已验收的 44 项测试是**已接受产物**，不得因内部机制变更而被迫改写
（改写已接受测试会削弱"验收即为冻结"的效力）；② 后续 P2/P4 直接消费这些浮点返回值
（统计、配对置换检验、融合），返回 dataclass 会静默破坏下游与 `pytest.approx` 比较。

**允许的实现方式**：内部另设一个返回 `SnrOutcome(value, denoiser_is_perfect)` 的函数
（如 `snr_outcome(s, x)` 或下划线私有），公开函数作为薄封装取 `.value`。
哨兵语义通过**附加函数**暴露，而不是改变公开返回值类型。
（即：机制可换，**接口不动**。）

**新增测试要求**：为哨兵语义加测试（完美输出时 `denoiser_is_perfect is True` 且
`value == math.inf`；双完美时 ΔSNR 为 `0.0` 且状态可查）；**P0.3 既有 44 项测试必须原样通过、
不得改动**。

**新阈值验收**：R9 完成后，纯代码 20-gram ≤2% 且 LCS ≤20 token（口径以签发方脚本为准）；
交付须报整改前后两组数值，并附你自建脚本的同口径数字作对照。
