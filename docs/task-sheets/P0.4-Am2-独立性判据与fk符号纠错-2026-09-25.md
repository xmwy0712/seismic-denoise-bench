二、裁定 2 · f-k 符号表述内部矛盾（必须修正）——R13
════════════════════════════════════════════

**发现**：同一批交付中两处表述**互相矛盾**：

| 位置 | 现表述 | 判定 |
| :--- | :--- | :--- |
| `src/bench/data/synthetic.py` docstring | `g(t,x) = W(t - x/v_app)`，并称"f-k 谱能量脊满足 **k = f/v_app**（f>0 时）" | ❌ **错误** |
| `tests/test_data_acceptance.py` L15–18 | `G(f,k) = W_hat(f)·delta(k + f/v)` → 脊在 **k = -f/v**，`f>0` 时 `k<0` | ✅ **正确** |

**依据（WorkBuddy 独立推导，用于裁定）**：`np.fft.fft2` 的核为 `exp(-2πi(ft + kx))`（**两个负号**）。
代入 `g(t,x)=W(t-x/v)`，令 `u = t - x/v`，指数化为 `-2πi(fu) - 2πi·x(f/v + k)`，
故能量脊满足 `f/v + k = 0` → **`k = -f/v`**（`f>0` 时 `k<0`）。
即：`k = +f/v` 只在混号约定（t 用正变换、x 用逆变换核）下成立，而 `fft2` 不是该约定。
这与你"初版按通用惯例 `f = v·k` 假定 `k>0` 导致三档全败"的诊断一致——根因就是**约定未写明**。

**修正要求**：
1. 改正 `synthetic.py` docstring 的符号表述，并**写明所用的变换核**，例如：
   "在 `numpy.fft.fft2` 的核 `exp(-2πi(ft+kx))` 下，脊线为 `k = -f/v`（`f>0` 时 `k<0`）；
   若改用 `exp(-2πi(ft-kx))` 约定则符号相反。**复现者须先确认核的符号**。"
2. 两处（`synthetic.py` 与 `test_data_acceptance.py`）**互相引用**，避免读者只看到一处而误判。
3. 该约定同时写入 P1 冻结清单（数据/指标相关的约定项）。
4. 交付须附一句自检结论：全仓库 grep 无残留的 `k = f/v` 类表述（除明确标注为"另一种约定"者）。
