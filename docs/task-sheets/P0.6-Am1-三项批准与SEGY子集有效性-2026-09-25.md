一、批准 ① 野外数据只取子集 —— 附**有效性验证**硬要求
════════════════════════════════════════════

**批准**：允许只取子集以省带宽。但必须按 SEG-Y 的**定长记录结构**做**按道（trace-aware）**截取，
不得按任意字节数截断。

**理由**：SEG-Y = 3200 B 文本头 + 400 B 二进制头 + N × 固定长度道记录。
任意字节截断会得到**打不开或元数据错乱的坏文件**，而且在 segyio 里可能表现为"能打开但道数/采样数错"，
属于**静默腐坏**——正是本项目最需要避免的失败类型。

**必须执行的步骤（缺一即视为子集无效，改用整文件下载）**
1. 先只取前 3600 B，解析二进制头：采样数（bytes 3221–3222）、格式码（3225–3226）；
   计算单道字节数并按格式码确定每样点字节宽度；
2. 若**道长度可变**（SEG-Y rev2 变长道）→ **放弃子集，改下载整文件**；
   该判断与依据须记入 execution-log；
3. 按**整数条道**做 HTTP Range 截取（含 3600 B 头），存为独立文件；
4. **用 segyio 实际打开该子集文件**，断言：道数与预期一致、采样数/格式码与头一致、
   无异常抛错。**任何一条断言失败 → 子集作废，改整文件下载**；
5. 记录：源 URL、取出字节范围、HTTP `Content-Length`、实际落盘字节数、
   文件 SHA256、抓取时间戳；整文件情形另需 `Content-Length == 落盘字节数` 的核对结论。

**其他要求**：代理凭据（若有）**不得**写入任何入库文件（仅 `.env`，已在 `.gitignore`）；
下载过程若走境外源导致失败，如实报告，不得改用来源不明的镜像。

二、批准 ② Semantic Scholar 限速应对
════════════════════════════════════════════

**批准**：退避重试 + 间隔 ≥1 s。**附加三条**：
1. **响应落盘缓存**：同一请求不得重复打网（重试与复跑均读缓存），既有省额度也可复现；
2. **逐来源计数披露**：`search-log.md` 须分别给出 Crossref / S2 / 人工检索的**实际入库条数**，
   不得只给总数；
3. **不得为凑数编造**：若某线的**可核验**题录确实不足 30 条，**停机报告实际条数**，
   不得以 `no-doi` 或"待定"条目填充至 30。该线的缺口如实记入覆盖限制小节。
（P0.5 的"每线 ≥30 条"由**多来源合计**满足；单来源不足不构成失败，只要如实披露。）
