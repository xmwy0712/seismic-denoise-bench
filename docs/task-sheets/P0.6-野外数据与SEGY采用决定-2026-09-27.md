────────────────────────────────────────
一、采用决定（WorkBuddy 已裁定，照此执行并落档）
────────────────────────────────────────
**采用 `segyio` 作为本项目的 SEG-Y 读取依赖**；`obspy` **不纳入**（保留为备选记录）。

依据与边界：
1. 二者官方许可均为 **LGPL-3.0**（已由签发方独立抽查确认：segyio raw LICENSE 原文、obspy PyPI 元数据）。
   LGPL-3.0 的传染性针对**库本身的修改版与再分发**；本项目**仅以 pip 依赖方式调用**，
   不复制源码、不静态链接、不随仓分发其源码 → **不触发对本仓库 MIT 代码的传染**。
2. **硬约束（写入 license-register 与 README 的许可段）**：
   - **禁止**把 segyio/obspy 的源码复制进本仓库任何位置；
   - **禁止**vendor / 打包其源码或二进制随 GitHub/Zenodo 发布；
   - 依赖通过 `pyproject.toml` / `requirements.lock` 声明，由使用者自行从 PyPI 安装；
   - 若**将来**需要分发其源码或修改版，必须重新核验并满足 LGPL-3.0 的 §2 修改标注、
     §3/§4 通告与随附 GPL+LGPL 全文义务（届时另行裁定）。
3. `segyio` 的 `external/` 子目录许可**未逐项取证**：因不 vendor、不复制源码，
   该缺口**不影响本次采用决定**；但须在 license-register 中保留该项并标注
   "仅在 vendoring 情形下需逐项核验"。
4. `obspy` 的"未纳入"理由写清（体量/依赖面更大；非许可问题）。
5. `license-register.csv`：把 segyio 行由"草稿"改为**"已核验 → 可用作 pip 依赖（不得复制源码/不得 vendor）"**，
   核验日填本日；obspy 行标注"已核验许可（LGPL-3.0）；本次不纳入（非许可原因）"。
   安装后新增的传递依赖（如 pyproj）须一并登记入"已核验"表。
