════════════════════════════════════════════
二、实现纪律
════════════════════════════════════════════

1. 每方法一个模块 `src/bench/methods/<name>.py`，**统一接口**：
   `run(noisy: np.ndarray, params: dict, rng: np.random.Generator) -> np.ndarray`
   （统一签名便于 270 观测矩阵运行；`rng` 显式注入，方法内部不得建全局随机源）。
2. **方法间独立性（守卫测试）**：任何方法模块**不得导入**其他方法模块或其输出；
   沿用 import 行扫描守卫（规则 14：只扫 import/from、脚本入库、自带反证）。
3. **DL 方法（若协议含）训练协议预注册**：数据划分、训练种子、epoch、early-stop、
   超参来源（论文默认 or 协议指定）——写成 `configs/training_protocol_draft.yaml` 提案，
   **交签发方批准后成为 P2 增补冻结件**；批准前**不得开始训练**。
   （这是多方法对比最常见的可信度缺口：逐方法调参即等于逐方法作弊。）
4. **先核官方文档**（集成类代码的铁律）：限速、API、参数含义；核验记录入 execution-log。
5. **不实现融合**（P3/P4 范围）；**不运行全矩阵**（P2.2）；不上云。

   - **同配置同种子两次运行 → 逐字节相同**（确定性判据，沿用规则 15 精神）；
   - 运行时间入账（供 P2.2 云成本估算）。
2. 方法登记表 ↔ 实现一致性自查表。
3. `pytest -q` 全绿 + **collected 数**；新增测试命名 `test_*.py`、入 collected 计数守卫。
