一、融合规则预注册（**两阶段**：规则草案 → 签发方确认 → 才打 tag / 实现 / 运行）

**阶段 1（Commit 1）· 规则草案 + 预注册件，然后停机等确认**

冻结框架（item_10 已冻）：三档 gamma 0.40/0.50/0.60，语义 `w′ = w·(1 − gamma·s)`。
本单要预注册的是 **w 与 s 的精确定义**。硬约束：

1. **融合不得接触真值**（无真值场景的方法）：
   - 模块输入**只有** `(y_i, y_j, params)` —— 函数签名**禁止** clean/s/mask 参数；
   - **AST 级守卫**：融合模块不得访问 ground truth / event_mask / frozen 真值路径；
   - w 与 s 只能从**两方法输出之间的关系**（局部一致性/相干性/能量结构）计算。
2. **w（局部保真度加权图）**：由你基于冻结机制族（局部相似度/正交化）提出候选定义，
   预注册件须给出：精确公式、窗格参数、归一化规则、**失效模式分析**
   （特别预答一个问题：**两方法输出高度相似≠两者都正确**——共线误差下局部一致性会虚高，
   你的 w 定义如何避免"一致即正确"的陷阱？）；
3. **s（相干噪声鉴别置信度，∈[0,1]）**：鉴别模块候选定义 + 语义（s→1 = 残余相干噪声证据强）
   + 与 CNA 子空间的关系（可复用注入基子空间做投影检测，但**输入仍不得含真值**——
   投影能量比是无真值量，预注册时写清楚）；
4. **输出聚合**：`y_fused = w1′·y_i + w2′·y_j`，权重归一化规则、边界/窗拼接规则；
5. 产出 `configs/fusion-rules-draft.yaml` + `results/fusion/preregistration.md`，**停机**。
